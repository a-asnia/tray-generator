# Генератор лотков — система контейнеров для 3D-печати

Параметрический генератор контейнеров-органайзеров: ячейки, стенки с узорами
(соты, линии), соединители «ласточкин хвост», экспорт в STL. Всё приложение —
один файл **`tray-generator.html`** в корне этого репозитория. Его не нужно
устанавливать или собирать: это готовая страница, которая целиком работает
сама по себе.

## Как залить приложение на свой сервер

Ровно три шага, ничего устанавливать не нужно:

1. Открой файл **`tray-generator.html`** здесь, на GitHub (кликни по нему в
   списке файлов в корне репозитория).
2. Нажми кнопку **«Download raw file»** (значок со стрелкой вниз, справа
   сверху над содержимым файла). Файл скачается на компьютер.
3. Залей скачанный файл на свой сервер — так же, как ты делал это раньше.
   Это единственный нужный файл: все скрипты и стили уже внутри него.

Готово. Открой страницу на своём сервере — генератор работает.

## Вставные перегородки

На вкладке «Модель» есть группа **«Вставные перегородки»**. Если её
включить, внутри контейнера печатаются направляющие, а сами перегородки
печатаются отдельной плоской деталью и вдвигаются сверху — их можно
переставлять и вынимать. Мест под вставку получается несколько (шаг
задаётся), деталь одна: печатайте столько копий, сколько нужно.
Скачать деталь — на вкладке «Принтер», кнопка «Скачать вставную
перегородку». Зазор по умолчанию 0,2 мм на сторону.

## Как сохранить свою работу

Всё, что вы настроили, само сохраняется в браузере — при следующем
открытии файла работа будет на месте. Чтобы сохранить проект отдельным
файлом (перенести на другой компьютер, сделать копию перед
экспериментами), откройте вкладку **«Принтер»** → группа **«Проект»**:

- **💾 Сохранить проект в файл** — скачается файл `tray-project-…json`
  со всей работой: контейнеры, раскладка, ячейки, стенки, фиксации,
  лимиты принтера.
- **📂 Открыть проект из файла** — выбрать такой файл и продолжить
  работу с того же места (текущая работа заменится содержимым файла).

## Как внести изменения в приложение

Попроси Claude (в новой сессии Claude Code на этом репозитории) сделать
нужное изменение. Claude поменяет исходники, сам пересоберёт
`tray-generator.html`, проверит его и закоммитит в корень репозитория.
После этого повтори три шага выше, чтобы обновить файл на сервере.

### Структура исходников

```
src/
  main.jsx               — монтирование React-приложения
  App.jsx                — панель UI с вкладками, редакторы, экспорт
  geometry/
    vec.js               — векторные операции
    solids.js            — выпуклые призмы, профиль стенки, пандус
    random.js            — детерминированный ГПСЧ, лента-«прядь»
    stl.js               — экспорт STL (мм, вертикаль — Z), объём, сварка вершин
    manifold.js          — ленивая загрузка Manifold (цельный STL)
  model/
    layout.js            — раскладка ячеек, ключи стенок, свойства стенок/ячеек
    connectors.js        — «ласточкин хвост»: константы, зоны, тела
    build.js             — сборка контейнера: стенки, узоры, пол-лесенка
  state/
    storage.js           — контейнеры по умолчанию, автосохранение, проверка
                           значений при загрузке проекта, экспорт/импорт .json
  scene/
    useTrayScene.js      — three.js: сцена, орбитальная камера, пикинг кликом
  ui/
    theme.js             — цвета и шрифты
    controls.jsx         — Param, Stepper, Collapse, SectionTitle
    Schematic.jsx        — плоская схема контейнера с выбором стенок/ячеек
tests/                   — проверки (см. ниже)
legacy/                  — исходный монолит v31 и старая CDN-сборка (справочно)
```

### Сборка (выполняет Claude в облачной среде)

Канонический артефакт собирает **офлайн-сборщик**, которому не нужны ни
npm, ни сеть — только Node и глобальный `tsc`:

```
node build.mjs     # → tray-generator.html в корне репозитория
```

Он транспилирует JSX (tsc → `React.createElement`), склеивает модули в
порядке определений исходного монолита и инлайнит библиотеки из `vendor/`
— это официальные UMD-сборки ровно тех версий, что раньше грузились с CDN:
React 18.2.0 (production, коммит релиза 9e3b772b8), three.js r128 (из
официального репозитория mrdoob/three.js, тег r128). На выходе один
самодостаточный HTML: все скрипты и стили инлайном, без CDN.

Единственное исключение — библиотека Manifold для кнопки «Скачать цельный
STL»: она, как и в оригинале, лениво подгружается с CDN при нажатии кнопки,
а при недоступности сети экспорт автоматически откатывается на обычный STL.

Параллельно настроен обычный путь через Vite + `vite-plugin-singlefile`
(для сред, где доступен npm; результат эквивалентен):

```
npm install
npm run dev          # предпросмотр на http://localhost:5173
npm run build:vite   # dist/index.html → tray-generator.html
```

### Проверки

```
npm test              # 10 наборов: геометрия и модель, без браузера
npm run test:browser  # 15 наборов: собранный HTML в headless Chromium
```

Браузерным нужен Playwright (глобальный тоже подходит — запускалка сама
подставит `NODE_PATH`) и уже собранный `tray-generator.html`.

Что именно проверяется:

- `fingerprint.mjs` — **отпечаток геометрии**: по 26 конфигурациям
  (узоры, пандусы, спуски кромок, боксы, замки, крайние толщины) сверяются
  число тел, треугольников, объём и хеш всех координат с эталоном
  `fingerprint.json`. Любой рефакторинг, который меняет геометрию хотя бы
  на 0.0001 мм, падает здесь. Осознанное изменение → `node
  tests/fingerprint.mjs --update` и эталон в коммит.
- `equivalence.mjs` — сравнение с ядром исходного монолита
  (`reference-v31.mjs`, вырезано из `legacy/tray-generator-v31.jsx`).
  Случаи, изменённые намеренно, помечены в самом тесте.
- `corners.mjs` — углы: валик обходит угол непрерывно, ничего не торчит за
  габарит, объём тела угла совпадает с расчётным (это ловит и щели между
  ломтиками, и горб), наружные плоскости сторон с замками ровные до угла.
- `rounding.mjs`, `fillets.mjs`, `fillet-audit.mjs` — скругление кромок и
  галтели во всех внутренних углах (аудит перечисляет все вертикальные
  рёбра и требует галтель на каждом подходящем).
- `clearance.mjs` — зазоры «ласточкиного хвоста» и производные размеры.
- `lines.mjs`, `locks.mjs` — выбор перегородки «по линии», замки ячеек и
  рядов, `fitSizes`, `minOuterDim`.
- `inserts.mjs` — вставные перегородки: шаг мест, ширина канала под
  толщину и зазор, деталь влезает между стенками, направляющие не спорят
  с пазами соединителей.
- `robustness.mjs` — битые и чужие файлы проектов, невозможные значения,
  краевые раскладки.
- `tests/browser/` — собранная страница целиком: рендер, пикинг кликом,
  скачивание STL, автосохранение, магнит соседей, фиксированные ячейки,
  экспорт/импорт проекта, восстановление после порченого сохранения.

После любых изменений геометрии прогоняются оба набора, и файл
`tray-generator.html` коммитится в корень вместе с исходниками.

### Инварианты (нарушать нельзя)

- Элементы одной ячейки никогда не пересекают внутренний объём соседней.
- Наружные плоскости внешних стенок идеально ровные: на них стыковка
  контейнеров и пазы соединителей (паз прячется внутри толщины стенки).
  Скругляется только сам вертикальный угол — тем же радиусом, что и верхние
  кромки: два валика не сходятся в остром углу (либо горб, либо щели).
  У стороны с замком угол остаётся острым, чтобы стыковка была плотной.
- Все размеры в миллиметрах; в STL вертикаль — ось Z.
- Узоры печатаются без поддержек: соты вершиной вверх, линии диагональные.
- Геометрия только аддитивная: выпуклые призмы, которые объединяются.
  Вычитания нет — «отверстия» получаются как промежутки между телами.

### Что стоит знать при правках

- **Материалы three.js создаются один раз** (`useTrayScene`): создание
  материала на каждую перестройку заставляет three.js заново компилировать
  шейдерную программу — на 9 контейнерах это удваивало время отклика.
- **Геометрия кэшируется по ссылке на объект контейнера** (`WeakMap` в
  `App.jsx`): обновления состояния делают новый объект только для
  изменённого контейнера, поэтому остальные не пересобираются.
- **Новый модуль надо добавить в `MODULES` в `build.mjs`.** Модули
  склеиваются в один скрипт, поэтому забытый файл не даёт ошибки сборки —
  страница просто падает в браузере. Сборщик проверяет это сам и
  отказывается собирать, но список всё равно ведётся руками.
- **Значения из файла проекта не доверенные.** `normalizeProject`
  приводит каждое число к разумному диапазону: одно `rows: 0` роняло
  построение, а поскольку состояние сразу уходит в автосохранение,
  приложение оставалось сломанным и после перезагрузки. Если что-то всё
  же упадёт, `Guard` в `main.jsx` показывает экран с кнопкой сброса.
